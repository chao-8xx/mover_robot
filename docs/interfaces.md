# 通信与数据约定

功能基线：0dcaf8b；核对日期：2026-11-12。串口表来自当前初始化代码，接线和设备版本仍需现场核对。

## 1. 主控串口分工

| 外设 | 波特率 | 用途 | 接收与处理 |
| --- | --- | --- | --- |
| USART1 | 115200 | OpenMV 与 Maix 共用摄像头通道 | DMA/空闲事件缓存，主循环 cam_task() 解析 |
| USART2 | 115200 | Emm V5 步进驱动器，地址 1～6 | 接收回调解析位置并重启 DMA；发送走 DMA 队列 |
| USART3 | 115200 | HWT101 IMU | 回调通知，TIM7 的 imu_task() 解析，imu_get() 更新连续角 |
| UART4 | 230400 | D6 雷达 | 接收 DMA，lidar_process() 消费数据；当前主循环调用被注释 |
| UART5 | 115200 | 串口屏 | 接收回调进入屏幕协议及应用事件 |
| USART6 | 115200 | 调试输出 | 调试缓冲与 DMA，TIM2 负责部分重试 |

所有配置入口见 [usart.c](../gongxun_1/Core/Src/usart.c)；事件路由见 [uart_dma.c](../gongxun_1/BSP/Src/uart_dma.c)。DMA 配置变化时需要同时核对回调、缓存寿命和重启方式，不能只修改波特率。

OpenMV 与 Maix 共享接收通道时需要约束发送者。Maix 程序包含 A16 TX 在 UART 与 GPIO 输入高阻间切换的逻辑；源码不能证明当前接线具备电气隔离，也不能证明设备已经正确释放总线。

## 2. 摄像头帧格式

~~~text
AA 55 CMD LEN DATA... SUM
SUM = (CMD + LEN + DATA所有字节之和) & 0xFF
~~~

| CMD | 方向/用途 | 负载 |
| --- | --- | --- |
| B0 | 主控停止视觉任务/释放发送 | 空负载 |
| B1 | 主控请求 OpenMV 扫码 | 具体发帧以 openmv_send_start_scan() 为准 |
| BB | OpenMV 返回任务码 | 固定 15 字节，形如 156+123+516+231 |
| B2 | 主控请求物料识别 | 一个颜色码 C1～C6 |
| B3 | 主控请求圆环定位 | 主控接口当前只接受 D2；拒绝 D1/D3 并保留原任务 |
| B4 | 主控请求码垛检测 | 一个颜色码 C1～C6 |
| B2/B3/B4 | Maix 返回结果 | FRAME_ID、OK、dxL、dxH、dyL、dyH，共 6 字节 |

颜色映射：C1 红、C2 黄、C3 蓝、C4 绿、C5 黑、C6 浅蓝。NOW 的 B2/B4 也接受数字 1～6；主控启动接口按协议码传参。B3/D2 完整请求示例：AA 55 B3 01 D2 86。

dx/dy 是低字节在前的 int16。有符号解码见 read_i16_le()。FRAME_ID 为 8 位，允许跳号和回绕；它用于去重，不是时间戳。回包不带颜色码，换颜色后晚到的同 CMD 旧帧无法仅靠协议区分。

## 3. 原始、有效、稳定是三层状态

- maix_vision：最新原始帧，含原始 OK、偏差和接收时间。
- maix_result.valid：最近 5 个唯一帧中至少 3 个有效目标，反映窗口历史。
- maix_result.stable：最新帧有效，并有 3 个候选坐标满足 X/Y 跨度限制。当前跨度阈值均为 0，含义是候选像素坐标完全相同。

NOW 的 B2 对外区分 OK=0 无目标、OK=1 找到、OK=2 满足抓取覆盖条件；B3/B4 只返回 0/1。**当前 F407 稳定判定已把 B2 的非零 OK 都作为候选，当前 OK=1 也可能 stable=1。** 旧的“稳定必须三个 OK=2”注释与测试不再匹配，详见 [验证记录](verification-2026-11-12.md)。

窗口 valid 允许短暂丢失，不代表当前帧有效。控制层 target_state_get() 当前用原始 maix_vision 的偏差跟踪，另外读取滤波 stable；不能认为控制已经统一使用中位数坐标。

超过 300 ms 没有新的唯一帧时，maix_result_task() 撤销原始/窗口状态。该机制依赖主循环继续运行，并不自动发送底盘或机构停止命令。抓取稳定计数在控制周期中递增，也不能直接当作独立相机新帧数。

B0、切任务、换颜色会清接收积压、半帧和滤波状态。现有联调使用停止 → 服务 200 ms → 清缓存 → 启动的顺序；这不构成对所有晚到同命令旧帧的协议级确认。

## 4. NOW 的当前运行设置与部署

入口 [main.py](../vision/maix_now/main.py)，版本见 [app.yaml](../vision/maix_now/app.yaml)：2.4.0，启动标记 NOW_B3_DIGIT_TWO_V14，配置 schema=14。

当前 run() 循环首个 rx_handle() 被注释；uart_control_active 初值为 False，后面的第二次接收受它控制。因此正常从 run() 启动时保持本地触屏调试，不能仅因后面仍有 rx_handle() 就认定主控接收入口开启。联调前应人工核对这一处开关，本次整理仅补充注释，未开启它。

部署须按 app.yaml 同步 8 个 Python 文件：main、vision_blob、vision_config、vision_ocr、vision_ring、vision_runtime、vision_tasks、vision_ui；不能只上传 main.py。包里的代码和当前工作区是否一致要另行检查，现有 zip 不会因源码注释修改自动更新。

配置文件 vision_now_config.json 优先覆盖源码默认参数。维护时同时记录：设备应用版本/模块标记、加载的 JSON 路径、实际生效的 ROI/参考点/LAB/面积，以及固件提交号。

| 项目 | 当前约定 |
| --- | --- |
| 图像参数坐标基准 | 320×240 原图 |
| B2 center | 原图绝对坐标，改变搜索 ROI 不应移动参考点 |
| B3/B4 center | 各自 ROI 内相对坐标，原图点 = ROI 起点 + center |
| B2 检测区域 | 搜索 ROI，扣除矩形/多边形屏蔽；grasp ROI 另做覆盖判断 |
| B3 | 几何稳定后确认数字 2，再跟踪圆心；不支持任意数字定位 |
| B2 发送节拍 | 28 ms |
| B3/B4 发送节拍 | 25 ms |
| LCD 预览节拍 | 100 ms，调试期约最多 10 次/秒 |
| 结果过期阈值 | 视觉侧 MAX_RESULT_AGE_MS=50；主控侧断流阈值 300 ms |

发送节拍、预览刷新和实际采集/检测/成功接收频率是不同指标。主控通信当前未启用时，配置周期不能当作实测发送率。

## 5. 电机接口与缓存

Emm_V5_Send() 把命令复制到全局环形队列，DMA 完成回调推进下一帧；不能把待 DMA 读取的数据改成生命周期不足的局部数组。队列满或 DMA 启动失败会返回失败，上层是否处理返回值需要逐条检查。

| 接口 | 数据含义 | 消费规则 |
| --- | --- | --- |
| Emm_V5_Get_Pos() | 机构沿用的旧位置表示，解析中有右移/旧标定语义 | 读取后清对应有效标志 |
| Emm_V5_Get_Pos_Sample() | 完整有符号位置和接收时间；底盘使用 65536 单位/圈 | 读取后清 sample_valid；与旧接口不能交换换算常数 |
| Emm_V5_Rx_Reset() | 清位置有效标志等接收状态 | 当前未清实际环形半帧长度，有跨复位拼帧问题 |

收到完整帧、发送队列空、动作 busy 结束、驱动器确认到位，分别是不同事件。四轮同步启动当前没有逐轮接受目标的上层确认，维护时应保留这些区别。

## 6. 位姿与道路状态

map_pose_update() 接收实际测量位置和测量时间，不能反复用旧位置配新时间维持 valid。接口检查有限数值、场地范围和 500 ms 过期；改变 yaw offset 会清旧位姿。

道路地图区分 unknown/free/blocked。没有看到障碍不能自动推出道路 free。独立 map_nav 需要可信位姿、停稳和道路观察许可，不能与比赛状态机同时控制底盘。详见 [道路导航专项说明](../gongxun_1/docs/map_nav_2026-10-21.md)。
