# 记录格式与采集要求

单位：距离、坐标为 mm；角度为 degree；有实测时间戳时为 ms。

## JSON / JSONL

标准记录包含 `format: "gongxun-lidar-v1"`、`synthetic`、`label` 和 `frames`。一圈可以写 360 项数组，也可以写稀疏 `points`。

```json
{
  "format": "gongxun-lidar-v1",
  "synthetic": true,
  "label": "格式示例：非实测",
  "frames": [
    {
      "scan_num": 1,
      "start_time": 0,
      "end_time": 100,
      "pose": {"x": 1200, "y": 800, "yaw_deg": 0, "valid": false},
      "points": [
        {"angle": 269, "distance": 700, "intensity": 100},
        {"angle": 270, "distance": 701, "intensity": 100},
        {"angle": 271, "distance": 700, "intensity": 100}
      ]
    }
  ]
}
```

实测时将 `synthetic` 写为 false，并在 metadata 中记录设备、摆放条件和来源。导入记录默认只表明“你提供的文件”，工具不会自行证明其真实性。

完整数组格式：`distance[360]`、`valid[360]`、`intensity[360]`，下标就是 0～359°。距离允许 0～65535；强度 0～255。有效距离不能是 0。没写 valid 时用 distance>0 推断；保留 valid 才能准确区分缺失角度与已有值。

稀疏 points：角度取整到 0～359；同整数角度多次输入时保留最近有效点及其强度。缺少的角度表示该圈没有有效样点，**不能用前一圈补齐**。有效点数小于 3 时仍能显示原始点，但当前聚类会拒绝。

JSONL 每行就是一个单圈对象，不需要外层 frames。JSONL 没有合成标记容器；示例文件名会注明 synthetic，使用时请保留来源说明。

scan_num 必须严格递增。跳号不会补造点云；地图会将跳过的圈计为候选漏扫。重新启动设备后的编号回到 1 时拆成新记录。

## CSV

每行一个样点，最少三列：

```csv
scan_num,angle,distance,valid,intensity,timestamp_ms,pose_x,pose_y,pose_yaw,pose_valid
1,269,700,1,100,100,1200,800,0,0
1,270,701,1,100,100,1200,800,0,0
1,271,700,1,100,100,1200,800,0,0
```

同一圈的时间戳和位姿必须相同。没有填写 pose_valid 则为 false。只填有效样点也可回放；需要分析盲区时，建议每圈输出全部 360 项 valid 与 distance。

## D6 原始二进制 `.bin`

文件必须是雷达 TX 的**原始字节**，不是十六进制字符串、终端截图或 UTF-8 文本。协议采用当前 `lidar.c` 的 AA 55、LSN、FSA、LSA、CS 与 3 字节样点规则，一包最多 25 个点。

至少包含两个合法单点起始包才能发布一圈；首次边界前的数据及末尾未结束圈不会发布。XOR 错误、非法角度或不合法起始包会按当前固件规则丢掉正在收集的工作圈，等待下一次有效边界。metadata.decoder 会报告错误统计。

字节文件默认没有有效位姿，没有实测时间戳，工具不会凭字节数假造扫描频率。若必须测时序，应另存带时间戳的完整圈记录。

## 如何取得第一份实测记录

先在固定车位采集 10～30 秒，记录车体原点、雷达安装高度、目标距离和位置。先无遮挡背景，再放目标；尤其保留细杆只命中 1～2 个角度的圈，不应先过滤后才记录。

有两种后续采集方案：

1. 用串口工具以二进制模式保存 D6 TX 原始字节。旁路监听时仅连接适配器 RX 与公共 GND，保持电平匹配；不要再接一条 TX 输出到正在工作的通信线上。优先在停车时采集。
2. 在现有固件输出完整圈快照 `lidar_scan_t`，至少包含 scan_num、distance、valid、intensity；停车位姿与时间戳放在同一圈记录内。需要安排发送带宽和缓冲生命周期，不能从不断更新的全局数组边打印边拼圈。

本工具没有启用或修改这两条采集链路。当前的 SCAN 四方向、WHEEL 100 圈统计、INSTALL 标定结果都缺少每圈完整数据，不能还原点云。以后采到一份文件，直接导入即可逐步判断：没扫到、被过滤、没聚类、被地图拒绝，还是确认后持续保留。
