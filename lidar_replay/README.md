# 雷达文件回放工具

双击本目录 **start.cmd**，浏览器会打开回放台。需要 Python 3.10 及以上；这台电脑现有的 Python 已验证可用。界面和算法均在本机运行，不需要安装额外 Python 包，也不需要联网。

停止工具：关闭启动窗口，或在窗口里按 Ctrl+C。端口被占用时，可在本目录运行 `python server.py --port 8766`。不要直接双击 `web/index.html`，它需要本地服务。

## 先用合成演示验收

启动后默认载入 40 圈合成样本。点击播放、上一圈、下一圈，或拖动进度条。向后跳转时，地图会从记录开头重放，保持多圈确认的正确历史。

| 圈数 | 演示内容 | 可核对的现象 |
| --- | --- | --- |
| 1～2 | 目标仅 1 / 2 点 | 仍能看到原始点，聚类因点数不足被拒绝 |
| 3～8 | 目标有 5 点并重复出现 | 形成聚类，连续匹配后障碍确认、影响道路变红 |
| 9～12 | 目标消失 | 当前源码仍保留已确认障碍与道路封锁 |
| 13～20 | 跨 359° / 0° 的点组 | 当前环形算法先收集整组，再判断点数；可试验四轮遮挡 |
| 21～28 | 缺 2° / 缺 3° | 缺 2° 能连接，缺 3° 会分段；仍需满足连接距离 |
| 29～34 | 超过聚类容量 | 显示因容量限制丢弃的候选 |
| 35～40 | 目标再次消失 | 对照持久地图状态，确认没有自动清路 |

右侧修改距离、连接距离、最少点数、遮挡区间或安装变换，再打开“与源码默认参数对比”。对比两套结果使用同一段记录与位姿，各自从开头累计地图。修改仅作用于电脑回放。

点击点云中的点可查看原始角度、距离、雷达/车体/场地坐标与过滤原因。聚类表显示接受或拒绝原因、所在格子与影响道路。地图显示原始包围框、安全膨胀范围和未知道路。

**合成样本只能验收软件，不能证明 D6 能检测真实细杆。** 样本车体尺寸 450 mm、安全余量 50 mm、位姿和 100 ms 圈间隔均为演示值。

## 以后导入实测记录

支持完整 JSON、单圈 JSONL、长表 CSV 和 D6 原始 `.bin` 字节文件，详见 [FORMAT.md](FORMAT.md)。文件上限 16 MB、最多 2000 圈；设备复位后扫描编号重新开始时，应另存一段。

没有位姿的记录默认 `pose.valid=false`：仍可检查局部原始点、过滤与聚类，场地地图不会更新。你明确知道停车位置和朝向时，才填写场地 X、Y、朝向，并将定位标为有效。朝向遵循当前 `tf2d.c` 的旋转公式：0° 时车体 +Y 对应场地 +Y；**不能直接假定它与底盘 `my_yaw` 的零点一致**。

导出问题帧会保存到本目录的 `exports` 文件夹，页面会给出文件名和下载副本的链接。保存原始输入、参数、当前与基准结果、源码信息和此前完整圈的上下文；重新导入时自动恢复参数、车体尺寸、对比状态和问题圈，复现累计地图。不同参数或不同回放位置需要重新计算时，工具会重建状态，不沿用旧结果。

## 算法对应范围

使用当前 `gongxun_1` 工作区（包含未提交修改），读取参数和地图布局。电脑实现是与 C 源码对照验证的 Python 副本：

- `lidar.c`：D6 XOR、起止角、强度/距离、整数角度取整、同角最近点与扫描边界；检测到坏包后丢弃工作圈。
- `obstacle_find.c`、`tf2d.c`：四轮遮挡、距离限位、极坐标转换、安装与位姿变换、相邻点环形聚类。
- `track_map.c`、`map_update.c`、`map_lidar.c`、`map_data.c`：场地格子、静态禁区、候选匹配、跨圈确认、车体膨胀和道路封锁。

当前地图是 9 节点 / 12 道路。格子用来说明位置，动态障碍实际封锁其影响的道路，不能把“落入某格子”理解成整个格子自动禁行。

当前确认阈值为 2 次匹配；候选连续漏 2 圈会删除，已确认障碍与道路封锁没有自动清除。道路初始状态是“未知”，没有障碍不能自动推导为“畅通”。当前默认四轮遮挡关闭，四组角度仍待实车标定。

回放按文件中的完整圈直接调用地图更新，不模拟 FreeRTOS 调度、DMA 实际丢字节、底盘停车条件、位姿恢复后等待扫描边界、路径规划和运动执行。文件里的 `pose.valid=true` 表示你确认该完整圈可用于场地映射。真实固件入口的等待规则仍以 `task.c` 为准。

二进制文件没有外部时间戳时，tick 使用起始包序号作占位，不能用于测量延迟或真实扫描周期。静默丢失整个包而没有坏包证据时，与当前固件一样，不能保证识别所有不完整圈。

## 自检与源码更新

在本目录运行：

```text
python -m unittest discover -s tests -v
```

C 对照测试需要主机 C 编译器；本机已使用 CLion 自带 GCC。也可设置 `LIDAR_REPLAY_CC` 指向编译器。没有编译器时，相关测试会明确跳过；这不等于已经完成 C 对照。

源码信息保留了验证时的文件 SHA-256，见 [source_snapshot.json](source_snapshot.json) 和 [VALIDATION.md](VALIDATION.md)。数值参数与布局会在启动时重新读取，但算法实现不会因固件修改自动改写。以后修改过滤、聚类或地图逻辑时，应重跑 C 对照并调整回放副本；文件摘要发生变化会提示重新验证。

本轮停止条件：合成样本可回放、导入/参数对比/导出可用、当前源码对照与边界自检通过、验收说明完整。真实细杆探测、安装标定、车体尺寸及现场位姿仍须实车验证。
