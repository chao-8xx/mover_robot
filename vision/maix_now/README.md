诊断开关同样在vision_config.py中，也可保存到本应用JSON：

```python
"color_diagnostics": True,
```

开启color_diagnostics后，仅B2黑色/浅蓝约每秒采样一帧，示例：

```text
[VISION B2 DIAG] UI TARGET=black WHY=AREA_REJECTED SIZE=220x200 MASK_PIX=3000/2000/1800 CUT=1000 TOP_AREA_PROC=[1700.0:LARGE] LIMIT_PROC=500..1500 CAND=1 SMALL=0 LARGE=1 PASS=0 LAB=[20,110,110]..[155,145,140]
```

示例数值仅解释字段，不是真机测量。MASK_PIX依次为阈值后/屏蔽后/形态学后的非零像素数，
SIZE与像素数都是实际处理图单位；TOP_AREA_PROC为最多三个候选的原始轮廓面积，不新增RUN面积换算。
SMALL/LARGE/PASS按实际处理阈值分类；LIMIT_PROC也使用处理图面积范围，LAB为当前生效的颜色阈值。
RUN经过缩放，诊断面积不能直接和UI数值对比；原有正常结果的坐标/面积映射及现场面积参数保持不变。
WHY分别为THRESHOLD_EMPTY、MASK_EMPTY、MORPH_EMPTY、AREA_REJECTED、SELECTED、NO_CENTER。
CUT只表示本采样帧总共被屏蔽掉多少颜色像素，不能单凭它断言真实物料被切掉；需结合MASK画面。
诊断复用一次LAB和现有轮廓遍历，仅采样帧增加计数，不改变最大合格色块选择，不清零或修改阈值。
切任务/颜色/保存会重置采样状态，正常连续运行最多约1Hz。
进入B2时GEOMETRY还会打印实际blob与当前LAB，先核对JSON是否覆盖了源码设置。

现场建议：到黑色/浅蓝阈值页的MASK，分别记录边缘/中间/无目标时的一张画面和一条DIAG。
现有JSON已有阈值、面积和多边形时仍优先使用；不要只改源码就认定真机参数已改变。

### B2新增抓取判定（独立于全图搜索）

唯一默认值入口是vision_config.py中的DEFAULT_CONFIG["grasp"]：

```python
"grasp": {
    "roi": {"x": 157, "y": 72, "w": 40, "h": 40},
    "min_coverage_pct": 60,
},
```

坐标以320×240原图为准。40×40、60%只是初试值，须在新镜头、横向夹爪及实际抓取高度下标定。
进入“任务一 → 调参 → 抓取判定区域”，选择X/Y/宽/高/覆盖阈值，使用加减及1/5/10步长修改，
实时预览草稿；保存写入同一个vision_now_config.json，恢复上次或返回放弃未保存修改。
已有JSON优先于源码默认值；改源码默认值不会覆盖设备已保存的抓取参数。
抓取框独立于center，调整它不会移动dx/dy参考点，也不会裁剪B2搜索视野。

覆盖率 = 本帧选中目标在抓取框内的有效掩膜像素数 / 完整抓取框像素数。
有效掩膜沿用当前LAB阈值及形态学档位。仍按原面积筛选和轮廓矩选择最大合格目标；
只在该候选外接框内，从其轮廓点种子提取8连通区域，并统计与抓取框的交集。
外接框只限制临时处理范围，绝不作为目标面积；不填满轮廓，不统计独立同色块/空洞内噪点。
若同色物料已经在现有掩膜中粘连，仍视作一个目标，本次不新增分离算法。

| B2当前帧 | OK | dx/dy |
| --- | --- | --- |
| 无有效目标 | 0 | 0/0，比例和旧坐标一起清除 |
| 有目标，未满足以下两个条件 | 1 | 原图基准正常偏差 |
| 重心在抓取框内，且覆盖率大于或等于阈值 | 2 | 原图基准正常偏差 |

中心范围采用半开区间x≤cx<x+w、y≤cy<y+h，右边界/下边界不计入。
RUN仍全图缩至240×180，抓取框左上向下、右下向上取整，分子/分母同时使用处理图像素单位。
中心沿用原dx/dy映射回320×240后判断；最多约一个处理像素的边缘采样差异属于缩放取整，
不要求UI/RUN逐像素相同。调参和RUN均采用同一“中心在框内且覆盖达标”规则。
无目标不做覆盖提取，目标与抓取框外接范围不相交时直接返回0覆盖；不新增全图转换/标记。

调试预览保留目标重心、参考点，新增抓取框及“OK=2 65.0% / 60%”式读数。
红色=无目标，黄色=找到但未达标，绿色=本帧达标。RUN调试画面限频更新比例，不逐处理帧刷新LCD。
2.2.2起，B2调参刷新的同一帧会显示真实选中轮廓，抓取框内实际计入覆盖率的像素染为青色；
未被阈值选中的亮面、空洞、其他独立同色区域不染色。底部PIX显示计数/总像素数，IN显示重心是否入框。
这是同一次连通区域提取产生的掩膜，既不填满外接矩形，也不另做一遍识别。
原图上看似物料覆盖90%不等于LAB有效像素覆盖90%；应对照青色和PIX确认分割是否漏掉物料。
若亮面/暗面未被选中，应在颜色阈值页观察MASK后实物调参；本版不自动放宽现场LAB。
青色逐像素计数预览只在UI显示时创建；RUN显示现有框/重心、覆盖率和PIX，不额外提取这份计数预览掩膜。
OK=2不是夹取指令、不是顶面识别、不是连续稳定确认；后续由F407决定连续确认和执行。

### B3：纯圆环中心

- 不识别数字、不加载OCR模板、不做椭圆修正。
- F407必须先把龙门架送到2号附近；纯几何视觉不能证明眼前圆环就是数字2。
- 下位机只应发B3 + 2或D2。1/D1、3/D3被忽略，不会切换视觉任务或取得TX所有权。
- 搜索阶段在可调ring.roi中筛选严格近圆、面积/外径合格、满足同心黑带层数的候选；
  优先选距离标定对准中心最近的候选，连续3帧几何位置一致后进入TRACK。
- TRACK阶段在上次圆心附近的动态窗口处理，只跟随48px以内的当前目标。
  动态窗口改变不改变dx/dy的原始标定参考点。
- 默认每5帧复核一次同心黑带，其他跟踪帧仍检查面积、尺寸及近圆程度。
  因此同位置圆形干扰可能暂时通过，但必须在下一次层数复核被否决；
  干扰多时把layer_check_interval改为1（帧率以实测为准）。
- 丢失立即LOST、RAW_OK=0、dx=dy=0；短时丢失保留锁定位置，
  下一帧回到标定ROI搜索；连续15帧丢失清空锁定重新确认。
- 为避免误认旁边槽位，现场应把B3的ROI框住2号附近且留足移动余量。
  不宜把三个圆环全放入过宽的ROI后期待程序识别编号。

### B4：单色码垛

与B2共享ColorTracker、原六色LAB阈值和形态学档位，任务三选择与调参菜单同样有六色。
因此这次迁入main的共享LAB同时作用于B2和B4；B4的ROI、中心和面积不跟随B2改动。
B4只检测指定颜色，独立使用stack.roi / stack.center / stack.blob，不跑三色。
只负责2号位置的码垛对准，另外两个位置由龙门架按标定位置移动，不识别层数。
源码现有stack.blob为1000～12000，stack.roi为(110,25,135,135)，本次未改变数值。
设备vision_now_config.json中已保存的面积、ROI和中心优先使用，尤其不覆盖降低后的最小面积。

## 性能和串口

RUN和调参页均显示限频实时画面，采集和检测继续独立运行；
预览正常最多约10Hz，画面的FPS是完整循环吞吐，LCD是实际刷新次数，两者不能混淆。

B2发送调度为28ms，目标约35.7Hz；B3/B4保持25ms，目标40Hz。
每个新图像结果最多发送一次，处理超时不补发旧坐标，不突发追赶。
处理开始到打包超过50ms时发送RAW_OK=0和零坐标。

用户2.1.1真机日志确认稳定B2处理吞吐39.0～39.4Hz、BUF=1，尚未达到40Hz。
2.1.2只恢复六色菜单/配置/指令，不把电脑实验中更慢的缩放替代方式引入真机程序。
2.1.3按用户要求只将B2发送调度改为28ms，不降低相机检测吞吐，切到B3/B4恢复25ms。
调度仍按时间节拍发送当前处理结果，实际包间隔受检测完成时刻影响，不保证每包精确相隔28ms。
实际成功发送率与包间隔须在正式串口模式测量，不能把28ms设置当作已达到稳定35.7Hz。

协议保持：
AA 55 CMD 06 FRAME_ID RAW_OK dxL dxH dyL dyH SUM
dx/dy为有符号16位小端，坐标仍为320×240基准。
B3只有TRACK且本帧found才发送RAW_OK=1。
仅B2允许OK=0/1/2；B3/B4继续为0/1。safe_xy_result、RUN映射、ResultSender和打包均保留B2状态2；
超龄结果强制OK=0、dx=dy=0。检测中到达停止/切任务/切颜色指令时丢弃整帧，不发送旧状态2。

启动/空闲/停止/退出时A16切为GPIO输入高阻，仅收到有效F407启动命令才取得UART0_TX。
B0为零长度停止命令。检测后再读取一次串口，收到B0或切任务命令就丢弃旧任务这一帧。
Python启动之前的系统串口日志不由本程序控制。

相机优先使用原生BGR888，并请求60FPS以避免主动限制在30FPS；
不支持则退回默认FPS，再不支持BGR则使用原有相机格式。
原生BGR可使用image2cv(copy=False)，默认RGB回退必须copy=True保证色序正确。
相关接口以设备固件为准：
[相机接口](https://wiki.sipeed.com/maixpy/api/maix/camera.html)、
[图像转换接口](https://wiki.sipeed.com/maixpy/api/maix/image.html)、
[UART接口](https://wiki.sipeed.com/maixpy/api/maix/peripheral/uart.html)。

调度目标与检测吞吐分开统计：B2目标35.7Hz发送，B3/B4目标40Hz发送，均以真机日志为准。
串口成功写入并不等于F407已收到并执行；这里没有修改F407滤波和运动闭环。

每秒输出VISION PERF：
- FPS：实际完整主循环每秒处理帧数。
- TXHZ：本窗口串口成功写入的结果帧数；本地模式为0。
- CAP/DET/DSP：每个处理帧平均采集转换/检测/显示耗时（ms），
  DSP按全部帧摊销；第一秒含页面缓存构建开销，观察后续稳定日志。
- LOOP95/MAX：完整循环耗时95分位与最大值，不能只看平均FPS。
- AGE_MAX/STALE：成功发送帧的处理时长上限/超时无效帧数。
  AGE从cam.read调用开始计，不包含不可知的传感器曝光时间、驱动缓存龄和F407延迟。
- B2/B4：CVT/THR/MORPH/BLOB为转换/阈值/形态学/轮廓阶段平均耗时，
  COLORS应为1，TARGET为当前颜色，FOUND表示本帧指定颜色是否找到。
- B2另有RESIZE为缩放/几何准备耗时，BUF=1为已启用输出缓冲区复用；
  B2 UI和RUN在支持dst时均应BUF=1，固件回退后BUF=0。比较同一场景稳定RUN的DET、BLOB、LOOP95和FPS。
  BLOB包含覆盖统计耗时，COVER单列其每帧平均耗时（无目标按0摊销，单位ms）；
  OK/COV是打印时最近一帧的状态/覆盖率，不是本秒达标率。
- B3：MASK/GRP/CTR/FLT为阶段平均耗时；ROI为本帧实际窗口，
  LAYER表示本帧是否复核黑带层数，LOCK/LOST/STATE表示跟踪状态。

可选tools/benchmark_camera.py：上传到与main.py同级后单独运行，
测15秒无LCD/无识别采集基线。READ_FPS只是Camera.read调用吞吐，
不代替曝光或新图像时间戳测量。
若基线本身明显低于40，则先检查设备固件、传感器帧率和曝光，
不能通过重复发送同一帧伪装40Hz视觉闭环。

### B2调试时查看OK和发送内容

任务一的调参页面和本地RUN都会打印：

```text
[VISION B2 PREVIEW] UI FPS=15.5 TXHZ=0.0 OK=2 DET_OK=2 WHY=ALIGNED IN=1 COV=60.0%/60% PIX=960/1600 C=(177,92) ROI=(157,72,40,40) D=(0,0) SEEN=2 HEX=AA 55 B2 06 01 02 00 00 00 00 BB
```

- PREVIEW：只是本帧检测结果的模拟打包，绝未因此打开UART/TX，不计入TXHZ；
  此模拟帧不经过正式发送调度/超时筛选，不能据此认定该帧能实际发送。
- TX：仅打印已成功写入串口的那一帧，HEX与真正发送的字节一致。
  正式模式未到发送时刻或写入失败时不伪装成TX，也不拿PREVIEW代替。
- OK：HEX帧的状态字节。DET_OK：检测状态，正式发送过期时可能DET_OK=2但OK=0。
- WHY=NO_TARGET：无目标，OK=0；CENTER_OUT：重心未入框；LOW_COVER：重心入框但覆盖不足；
  ALIGNED：中心与覆盖同时达标，检测OK=2；STALE：正式发送的结果已过期，强制OK=0和零偏差。
- IN=0/1：当前目标重心是否在抓取框内；COV显示当前比例/实际设定阈值，
  ROI是320×240抓取框，C是目标重心，D是帧中的dx/dy。覆盖70%仍为1时先看IN和实际阈值。
- SEEN是本打印窗口出现过的检测状态。例如SEEN=1,2表示有短暂的达标帧，
  当前HEX仍只对应当前采样帧，不回放或补发该短暂帧。
- FPS/TXHZ沿用最近一个完整统计窗口的循环吞吐/成功发送率，仍保留每秒VISION PERF详细日志。
  切任务/颜色/运行模式后先归零，首个完整窗口后更新，避免把上一模式帧率显示为当前值。
  画面FPS与日志FPS口径相同，LCD是实际预览刷新率，不能把LCD当作检测FPS。
- PIX是覆盖率的分子/分母；例如799/1600=49.9%，可对照青色掩膜核验。
  RUN的PIX按240×180处理图统计，UI按320×240；分子/分母始终采用相同像素单位。

稳定状态约1Hz打印，状态/原因变化最多5Hz，避免每帧十六进制打印拖慢循环；
任务/颜色/运行模式切换或保存参数后清空诊断窗口，不遗留旧任务的状态。
首个状态即打印。通过日志采样无法逐帧重建变化时刻，实发逐帧验证应使用独立串口接收器。

### B2/B3/B4分别验收新鲜更新率

在正式串口控制的RUN页测量，每组至少记录30秒，跳过首次绘制和任务切换的过渡窗口。
本调试版包含限频LCD开销；若之后关闭显示，应重新测量，不能直接套用本版数据。

| 任务 | 测量场景 | 需要核对 |
| --- | --- | --- |
| B2 | 分别指令原六色；其他颜色同时出现；目标移到四角再移出画面 | COLORS=1；仅指定颜色的坐标变化；全视野可见；消失后RAW_OK=0 |
| B3 | F407先到2号附近；记录SEARCH/CONFIRM和稳定TRACK；移动、遮挡并恢复圆环 | 分阶段记录FPS/TXHZ；动态ROI不移动对准参考；丢失立即无效；按原规则恢复 |
| B4 | 在2号位置分别指令原六色，使用实际不同码垛高度 | COLORS=1；使用独立ROI/中心和已保存的小面积阈值；无层数识别 |

每组记录CAP/DET、FPS、TXHZ、LOOP95/MAX、AGE_MAX/STALE。
FPS是每次cam.read后的完整处理吞吐；TXHZ包含成功发送的有效及无效结果，不是有效定位频率。
检测不到目标时发送新一帧的RAW_OK=0是正确行为，不能为了指标继续上传上次坐标。
在目标持续可见的场景，还应在串口接收端分别统计全部包、OK>0包及B2的OK=2包实际频率、间隔和丢包。
FRAME_ID按处理帧递增、按8位回绕；发送限频或切任务可能造成跳号/重置，不能把跳号都算作丢包。
移动目标并对照串口坐标/画面（必要时同步录像），确认结果跟随新画面；
日志无法证明驱动缓存中每次返回的都是不同曝光，若固件提供采集时间戳/帧序号应一并核对。
只在真机数据证明B2持续发送约35.7Hz、B3/B4约40Hz的新结果后，才能确认各任务目标达标；
确认阶段的RAW_OK=0、丢失恢复及高曝光时的帧率变化应单独报告。
