## 文件职责

- `main.py`：硬件初始化、唯一主循环、串口/触摸任务选择、显示和发送。
- `vision_config.py`：默认参数、参数校验、LAB/HSV阈值和JSON持久化。
- `vision_blob.py`：B2/B4共享的颜色MASK、最大色块、RUN缩放和坐标恢复。
- `vision_ring.py`：B3灰度黑色MASK、严格圆形过滤、同心环带确认。
- `vision_ocr.py`：低频判断一个候选“是不是2”，1/3只作为负样本。
- `vision_tasks.py`：共享`ColorTracker`、`RingTask`和单任务调度。
- `vision_ui.py`：三任务首页、共享颜色页面、2号圆环调参页面。

`app.yaml`列出以上七个运行文件，`README.md`不上传到设备。

## 三个任务

### B2：物料识别

沿用已真机验收的颜色路径。每帧只处理当前指定颜色并输出`found/cx/cy/dx/dy/area`。

### B3：2号圆环定位

处理顺序：

```text
任务二可调ROI内生成黑色MASK
→ 断续同心环归为一个候选
→ 面积/直径/圆度/短长轴比过滤
→ 正圆12方向黑带层数确认
→ 选择最靠近任务二对准中心的候选
→ 连续稳定3帧
→ 低频确认“是不是2”
→ TRACK阶段只跟踪上一次圆心，不再运行OCR
```

候选短轴/长轴比低于0.85直接拒绝。任务二没有椭圆拟合、1/2/3目标选择、
左中右槽位、三数字投票或常态OCR。OCR不能确认时保持未知，每隔8帧重试；
确认2后立即停止OCR。短时丢环进入`LOST`，但保留“已经确认是2”和上一次圆心；
15帧内只在上次圆心48像素附近重捕获，不再调用OCR。连续15帧仍未找回才清空确认，
回到`SEARCH`重新识别。这既避免一两帧抖动反复OCR，也防止长时间遮挡后锁到错误目标。

程序启动时提前生成并缓存12张字体模板。因此第一次B3确认不再承担模板初始化耗时；
这只把一次性耗时前移到启动阶段，不会提高稳定TRACK阶段本来就已经停止OCR的帧率。

### B4：码垛堆放

B4与B2使用同一个`ColorTracker`实例和同一套LAB/HSV颜色阈值、模式和形态学路径，
但任务三已经拥有独立的`stack.roi/center/blob`。这些参数默认仍为完整320×240、
图像中心和300～60000面积范围，后续只需根据真实码垛画面调节，不需要复制算法。
切换B2/B4时会清空共享识别器的RUN缩放缓存。B4与B2一样，当前帧找到目标时
发送有效坐标，未找到时发送`RAW_OK=0, dx=0, dy=0`。

## 本机与正式运行

本机调试时注释主循环中的`rx_handle()`，由首页三个按钮选择任务。正式运行时
恢复该调用，由F407的B0/B2/B3/B4选择任务。新版B3只接受目标码`0xD2`；
B3携带1或3时不会切换任务。

主程序每轮只读取一次相机，也只运行当前一个检测器。任务切换会清空圆环确认、
旧圆心和颜色RUN缩放缓存。

## 参数与坐标契约

- `roi.x/y/w/h`、`center.x/y`和面积范围始终按320×240保存。
- B2/B4内部240×180只用于RUN加速，不写回配置。
- B2使用根级`roi/center/blob`；B4使用独立`stack.roi/center/blob`。
- `ring.roi`按完整320×240坐标保存并可在任务二调参页拖动；检测仅处理ROI内部。
- `ring.center`是选择2号候选和计算`dx/dy`的独立对准中心。
- `ring.min_diameter/max_diameter`按320×240像素定义。
- 所有任务离开检测器前都恢复为320×240的`cx/cy/dx/dy/area`。

## 真机检查

正确版本启动时应输出：

```text
[VISION BUILD] B234_TX20_LIVE5_RINGROI_TXHIZ_V16
[VISION OCR] warmup ready templates:12 cost:...ms
```

屏幕左上角`V:`是实际识别帧率，`D:`是屏幕刷新帧率。本版目标是
`V:20.0`以上、`D:`约5.0；必须以MaixCam实机稳定RUN数值为准。

B3稳定RUN日志格式：

```text
[RING PERF] RUN FPS:... CAP:...ms DET:...ms DSP:0.0ms MASK:... GRP:... CTR:... FLT:... OCR:...(...) S:... M:... R:... CAND:... CNT:... GEOM:... REJ:... LAY:... DIR:... AR:... SEL:... TWO:... LOST:... STATE:...
```

- `DSP:...ms`：RUN每200ms最多刷新一次LCD，这里是实际显示平均耗时。
- `AR`：候选旋转不敏感的短轴/长轴比，合格值不低于0.85。
- `SEL:1`：当前已经选中最靠近对准中心或上一次圆心的候选。
- `TWO:1 STATE:TRACK`：已经确认数字2并进入纯圆心跟踪。
- `OCR:x(n)`：本周期OCR平均耗时与调用次数；TRACK后`n`应为0。
- `S/M/R`：最近一次确认的2号分数、相对负样本差值和判定原因。`S`越小、
  `M`越大越可靠；通过时应为`R:TWO`。归一化成功但未通过时，`SCORE`表示
  分数过高、`MARGIN`表示与1/3差距不足、`SCORE_MARGIN`表示两项都未通过；
  裁剪或字符形状失败还可能显示`NO_GLYPH/ASPECT/FILL`等。
- `TWO:1 LOST:n STATE:LOST`：目标暂时消失，但2号确认仍保留；重新出现后应直接
  回到`TRACK`且`OCR`调用次数保持0。`LOST`达到15后才回到`SEARCH`。
- `REJ`：依次为`AREA/SIZE/RATIO/CIRC/LAYER`淘汰数量。

真实打印目标建议分别测试：中心放2、中心放1、中心放3、快速移动2、短时遮挡2。
中心放2时记录首次`R:TWO`的`S/M`，并观察是否通常一次确认；中心放1/3时必须始终
`TWO:0`。如果2经常出现`NO_GLYPH`，优先检查字符裁剪是否完整；
经常出现`ASPECT/FILL`，检查拍摄尺寸和二值化后的字符形状；如果肉眼看裁剪正常，
但长期出现`SCORE/MARGIN/SCORE_MARGIN`，则再采集2到4张真实打印数字2模板，
不要先增加更复杂的OCR算法。

圆环ROI必须完整包住目标圆环，并在最外圈四周保留少量余量。ROI裁断外圈时，
层数、圆度和12方向检查都会变差；对准中心坐标是ROI内部相对坐标，但最终发送的
`cx/cy/dx/dy`仍恢复到完整320×240坐标系。

B3发送与B2使用相同数据布局：`FRAME_ID RAW_OK dxL dxH dyL dyH`。只有
`STATE:TRACK`且当前帧`found`时`RAW_OK=1`；`SEARCH/CONFIRM/LOST`以及任何
未找到目标的帧都发送`RAW_OK=0, dx=0, dy=0`，不会泄漏上一帧旧坐标。

B4同样使用上述六字节布局，命令字为`0xB4`。任务三不复制颜色算法：`mode`、
`morph_mode`和LAB/HSV六色阈值直接引用任务一配置；只有`stack.roi/center/blob`
属于任务三，用于现场单独设置码垛搜索范围、放置对准中心和面积限制。

电脑端生成图和性能只能作为回归，不能替代MaixCam上的真实字体、距离、灯光、
帧率、圆心抖动和丢失恢复验收。
