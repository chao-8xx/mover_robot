- 相机输入：320×240。
- HOME 和调参页面：完整 320×240 处理。
- 任务一 RUN：当前 ROI 按 320×240 → 240×180 的比例缩小后处理。
- 任务二：固定完整 320×240 搜索，RUN 页面停止周期刷新LCD。
- 形态学默认档位：`OPEN_ONLY`。

- 三任务首页已接入：任务一运行现有物料识别，任务二运行圆环候选检测，任务三为安全占位。

帧率结果只证明当前运行速度，不能代替识别准确率、坐标抖动、误识别和丢失恢复测试。

## 文件职责

- `main.py`：硬件初始化、唯一主循环、串口/触摸任务选择、显示和发送。
- `vision_config.py`：默认参数、参数校验、单套 JSON 加载与保存。
- `vision_blob.py`：颜色阈值、形态学、最大色块、RUN 缩放和结果映射。
- `vision_ring.py`：任务二灰度黑色MASK、断续环带验证、候选绘制。
- `vision_tasks.py`：轻量任务管理器、任务一/二单帧封装、任务三安全占位。
- `vision_ui.py`：三任务首页、任务一/二页面、占位页、触摸和屏幕坐标映射。

`app.yaml` 列出以上六个运行文件。`README.md` 不上传到设备。

## 当前任务边界

- 任务一：物料识别。沿用已经真机验收的B2算法、配置和240×180 RUN路径。
- 任务二：数字与圆环定位。当前完成黑色MASK、全画面尺寸过滤和同心候选；
  尚未接入数字OCR，不向F407返回B3有效坐标。
- 任务三：码垛堆放。当前只显示占位页，不复用B2结果冒充码垛定位。

主程序每轮只读取一次相机，并只把当前帧交给一个任务。切换任务时，任务管理器
会清空上一个任务的运行几何和历史状态。

本机调试时注释主循环中的 `rx_handle()`，由首页三个按钮选择任务。正式运行时
恢复该调用，由F407的B0/B2/B3/B4选择待机、任务一、任务二或任务三。

## 坐标与参数契约

用户在菜单中修改和保存的参数始终以 320×240 为基准：

- `roi.x/y/w/h`：相对于完整 320×240 图像。
- `center.x/y`：相对于 ROI 左上角。
- `blob.min_area/max_area`：320×240 下的等效轮廓面积。
- `ring.roi`：固定为完整 320×240；旧JSON中的任务二ROI会在加载时迁移。
- `ring.center`：任务二独立对准中心，不影响任务一参数。
- `ring.min_diameter/max_diameter`：320×240下的圆环候选外径范围。
- `cx/cy`：映射回 320×240 后的目标绝对坐标。
- `dx/dy`：目标中心相对抓取中心的偏差。

240×180 只存在于 RUN 内部。小图坐标、ROI 和面积阈值不会保存到 JSON，也不能直接发送给控制器。

## 两条执行路径

调参路径：

```text
320×240 相机图像
→ 320×240 基准 ROI
→ 阈值和形态学
→ 最大色块
→ RAW / MASK / OVERLAY
→ UI 和屏幕显示
```

任务一 RUN 路径：

```text
320×240 相机图像
→ 裁出基准 ROI
→ 按 0.75 比例缩小
→ 阈值和形态学
→ 最大色块
→ 坐标和面积映射回 320×240
→ blob_result
```

任务二始终在完整 320×240 上寻找圆环候选，不进行任务一的缩图处理。任务一和
任务二的 RUN 都只在进入时显示一次静态页面，不生成预览，也不周期调用屏幕刷新。
任务二每秒打印一次 `CAP/DET/DSP`，用于区分相机转换、候选检测和LCD显示开销。

## 真机运行检查

MaixVision 必须使用“运行项目”，并确保六个运行文件同时从磁盘重新加载。正确版本启动时会输出：

```text
[VISION RUN] process: 240x180; config coordinates: 320x240
[VISION BUILD] B3_DILATE7_RECT_PROFILE_B2_RUN240_V4
```

RUN 性能行中的：

- `ROI:320x240->240x180` 表示基准 ROI 和实际处理 ROI。
- `RSZ` 表示缩放耗时。
- `MASK` 包含颜色转换、阈值、开/闭运算。
- `XY/DXY/AREA` 已经映射回 320×240。

如果修改了磁盘文件，应先让 MaixVision 重新加载全部标签页，避免旧编辑缓存覆盖新代码。

任务二正式RUN时还应看到类似下面的性能行：

```text
[RING PERF] RUN FPS:... CAP:...ms DET:...ms DSP:0.0ms MASK:... GRP:... CTR:... FLT:... CAND:... CNT:... RAY:...
```

其中稳定运行后的 `DSP:0.0ms` 表示周期LCD刷新已经关闭；`CNT` 是分组后的
外部轮廓数，`RAY` 是真正进入12方向黑带检查的候选数。首次进入RUN时仍会显示
一次静态页面。电脑端基准不能代替MaixCam真机帧率和真实场景识别验收。

分段耗时中，`MASK` 是灰度阈值，`GRP` 是单次矩形膨胀，`CTR` 是外部轮廓
提取与兼容整理，`FLT` 是几何过滤和黑带层数检查。
