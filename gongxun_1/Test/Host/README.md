# camera 接口和验证

只涉及 `BSP/Inc/camera.h`、`BSP/Src/camera.c`、摄像头测试；不修改控制、PID、运动或夹取流程。

## 结果约定

- `maix_vision_t.ok` 和新增的 `maix_result_t.ok`：最新接收帧原始状态。B2允许0/1/2，B3/B4允许0/1；非法状态整帧丢弃。
- `valid_count`：最近五帧中有效目标的数量，B2的1和2都计数，**不是OK=2的数量**。`valid`仍是窗口至少三帧有效。
- B2 `stable`：当前帧OK=2，且最近五帧中至少三个OK=2的坐标满足原有X/Y跨度阈值。不要求连续，不借用OK=1的坐标凑稳定。
- B3/B4仍取窗口中OK=1的三个坐标作原有跨度和中位数判断；当前OK=0时不报stable。
- 最新OK=0或B2最新OK=1不清窗口。单帧丢失时`valid`及滤波坐标可以暂时保留，`ok`表示当前帧，不能把历史`valid`理解为当前帧发现目标。原始OK=0的dx/dy强制为零。
- `stable`时输出最佳三点中位数；未稳定但`valid`时取全部有效点中位数；无窗口有效性时滤波坐标为零。
- 超过现有300ms没有新帧，原始及滤波OK/坐标/窗口都失效，两套读取接口各通知一次。重复帧不刷新时间；超时后同一个旧ID也不能重新激活结果，新ID到达后重新建立窗口。
- 帧号允许跳号和255→0回绕。B0、切任务、换颜色清原始/滤波及去重状态，并丢弃当时DMA积压字节和半帧；没有新增等待或握手。返回帧不携带颜色，切换后才到达的同CMD旧颜色完整帧仍不能仅靠协议辨认。联调可沿用现有测试中的B0→200ms服务→清缓冲→启动顺序。
- B3启动仅接受D2；D1/D3打印拒绝，保留此前任务，不发送替代命令。
- 帧格式、校验和、UART接线不变。camera不控制电机，`valid/stable`都不是夹取指令。

## 真机通信验证

不在本次修改中切换 `main.c` 测试入口。人工单独选择已有 `maix_b2_test()`，保留接收处理；Maix需启用串口指令接收。该函数只测试摄像头通信，不调用运动接口。

1. 移开目标，观察OK=0及原始零偏差；移入画面但不满足抓取条件，观察OK=1、valid建立、stable=0。
2. 达到抓取ROI和覆盖要求，观察OK=2；窗口至少三个OK=2坐标满足原跨度时stable=1。短暂移出判定区域，stable撤销但窗口不清；恢复后重新评估。
3. 观察日志中的 `ok/samples/valid_count/valid/stable`；汇总 `新帧RXHZ` 是本次测试首末接收帧间的独立新帧频率，不是Maix采集帧率或性能承诺。
4. 测试B0、换颜色、B3/D2、B4；综合测试已有断流检查，现在同时检查原始及滤波失效。

桌面通过和工程编译通过均不能代替真实UART、接线和机械验收。控制层对OK=2和失效状态的使用由队友适配。
