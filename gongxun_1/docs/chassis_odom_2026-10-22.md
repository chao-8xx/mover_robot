# 底盘反馈、里程计与地图位姿

本次沿用`task_state.x_cm / y_cm`和`my_yaw`，补齐反馈到地图位姿的处理。整车主循环通过`map_pose_test()`进行真实位姿静止建图，未启动`map_nav`，固定测试位姿的雷达建图入口保留为可切换测试。

## 反馈与换算

Emm_V5的`0x36`回复为8字节：地址、命令、符号、4字节大端位置、`0x6B`。符号`00`为正、`01`为负，一圈对应65536。参考[Emm_V5.0 Rev1.3说明书转载，读取电机实时位置章节](https://github.com/Emiraen/26autogo_transport/blob/main/docs/Emm_V5.0%E6%AD%A5%E8%BF%9B%E9%97%AD%E7%8E%AF%E9%A9%B1%E5%8A%A8%E8%AF%B4%E6%98%8E%E4%B9%A6Rev1.3.md)。仍需用车上驱动器的真实回复核对型号、方向和比例。

- 新接口`Emm_V5_Get_Pos_Sample(addr, &pos, &tick)`返回完整带符号位置和完整帧的接收时间，取走后清除本接口的新数据标志。
- 原`Emm_V5_Get_Pos()`继续返回原3字节标定读数，供升降、伸缩使用。它仍沿用原先忽略符号字节的语义，不能用于底盘里程计；夹取模块的反馈单位与方向统一留待单独复测。
- 底盘控制命令仍使用3200脉冲/圈；反馈单独按65536单位/圈换算，轮径继续用原7.9cm，横移系数继续用原1.10。
- 接收支持拆帧、连续多帧和噪声后重新同步。半帧间隔超过20ms丢弃；串口错误清除半帧与缓存反馈，并使里程计失效。

## 调用与起点

`main.c`主循环调用`chassis_odom_tick()`。内部每20ms读一个轮子，移动、旋转、静止均轮询；四轮都收到新反馈，且接收时间跨度不超过80ms、年龄不超过150ms时才计算增量。接收时间是采样时间的近似，当前协议没有测量序号，四轮也不是硬件同步采样。

```c
// 按赛场图：启停区2在右下角，车体原点位于区中心，车头朝北归零
chassis_odom_origin_set(225.0f, 15.0f);  // cm
// 后续在主循环持续调用，等第一组四轮反馈建立基准后再移动
chassis_odom_tick();
```

地图原点为赛场图左下角，X向右、Y向上。原串口屏`CC 00`选择右下启停区2，实际坐标为`(225,15)`cm；`CC 01`选择右上启停区1，为`(225,225)`cm。这两个值按300mm启停区中心计算；车体定位原点没有放在中心时，必须填写实测位置。旧比赛的格子编号和任务控制保留，不与实际毫米坐标直接混用。选择发车点本身不发送移动命令。启停区坐标不直接当作导航节点。

首次采样只建立轮子基准。若基准尚未建立车辆已经收到运动指令，则位姿失效，不能把已经移动后的轮子位置冒充起点。设置起点前必须先停止速度指令；函数对忙状态、非零车体指令、非法坐标返回0。

车体增量按地图朝向偏移变换；按实际发车姿态朝北归零，默认`my_yaw=0`朝北、`+90`朝西、`-90`朝东，地图角度偏移为0。转向期间使用相邻两次朝向的中间值近似积分。计算完成后把cm乘10，通过原`map_pose_update()`发布mm位姿。时间取四轮反馈与角度帧中最旧的接收时间，重复执行主循环或只更新某一个轮子不会刷新位姿时间。

## 当前静止测试步骤

1. 整车模式使用`LIDAR_PILLAR_TEST_ENABLE=0`；独立2m小柱测试设为1时，不执行里程计和真实位姿建图。
2. 车辆实际放在右下启停区2，车体定位原点为`(2250,150)`mm，车头朝图上方。保持静止，等待开机IMU归零结束；若手动归零，也先等结束再设置起点。
3. 不需要操作串口屏。保持车辆朝北、静止，按开发板KEY1（PC1）约0.2~0.5秒后松开。任务用30ms消抖，松开时只确认一次起点，不发车、不归零IMU。看到`[POSE KEY] 启停区2起点已确认=(2250,150)mm，等待四轮新反馈；未发车`后继续等待；这条日志本身不代表四轮反馈已有效。运行中或IMU未就绪会拒绝本次按键，按提示处理后重新按键。
4. USART6调试串口115200，检查`[POSE MAP] valid=1 xy≈(2250,150) yaw≈0 chassis=0`；位姿age应保持小于500ms，`[POSE SCAN] raw/accepted`应持续前进。`valid=0 imu=0`先检查IMU；已确认起点且`imu=1`仍无有效位姿时，再检查四轮反馈。只靠按键不会绕过反馈有效性检查。
5. 在雷达0度与车头一致、安装偏移近似零的条件下，从雷达量正前方约500mm的小柱回波位于`(2250,650)`附近，属于R11。当前静止入口观察N8->N5方向，同位置候选在最近5个新扫描中命中3次后确认封路；最终检查`R11=BLOCKED`。安装偏移仍需按实测设置，其他道路状态还受现场其他物体影响。
6. 已封锁道路不会因移走小柱自动解封。重新做空场对照时复位开发板，保持朝北，再短按KEY1确认起点。再次按键只清除旧位姿和待确认次数，保留已封锁道路。每次按键都要求车辆确实位于右下启停区2，不能在其他位置借此恢复定位。IMU再次归零后也须在正确位置重新确认起点。

## 正面小柱没有封路时的诊断

保持原来的启停区2、朝北、静止、短按KEY1操作。位姿有效后，每2秒额外输出一组正面诊断；不需要再按键，不改变筛选阈值或发车状态。

- `[POSE FRONT]`：扫描编号、采集年龄、整圈有效点数、保存的聚类数和截断标志。只有原始扫描、点云、聚类及accepted对应同一圈时才输出细节；`waiting same scan`表示本次尚不能逐点对照。
- `[POSE RAW]`：雷达原始352~359、0~8度。每项`角度=距离mm/原始有效/点云有效`，例如`0=700/1/1`表示该整数角度有700mm回波且进入点云。它是合并后的整数角度结果，不是协议中的全部原始采样。
- `[POSE CLUSTER]`：正面聚类的角区、点数p、最近距离near、平面跨度span、地图位置xy、小柱筛选pillar和真实点涉及的道路roads。每组最多打印3项，包含筛选失败的大聚类；`front/pillar/shown`分别为正面保存的聚类数、通过小柱筛选数、实际打印数。近处不足3点的组不会保存，应同时看RAW。
- `roads`只表示几何归属，不表示已经确认封路。R11对应`0x800`，多个道路命中时按位组合。继续结合已有`[OBSERVE]`的now、pending、block和`[OBSERVE C...]`的hits查看确认过程：当前任务方向采用最近5个新扫描命中3次，最终以`[POSE ROAD]`为准。

先移走黑柱记录约10秒空场，再将比赛黑柱放到车头前600mm处（本车估计距雷达柱面约700mm），人和卷尺离开扫描平面，静止记录约10秒。确认雷达扫描面穿过100mm高的柱身。若0度与车头一致且安装偏移近似零，700mm回波的地图位置应在`(2250,850)mm`附近，属于R11。

RAW没有目标距离时先查扫描高度、遮挡和方向；RAW有点而聚类没有时查有效整数角数与分组；`pillar=0`查点数和跨度；`pillar=1`但没有确认时查地图坐标、道路归属及OBSERVE窗口。这些日志用于定位原因，不能单凭accepted递增判定黑柱已检出。

## 失效与恢复

- `chassis_odom_hold()`使实际起点失效。原先将`odom_on`重新置1不能恢复有效地图位姿，必须静止后重新调用`chassis_odom_origin_set()`确认位置。
- 四轮有效采样中断超过500ms、角度帧超过100ms、IMU错误/归零、地图角度偏移改变均使位姿失效。角速度/加速度帧不能延长角度有效期。
- `chassis_odom_reset()`用于车辆静止、编码器清零后重建轮子基准，不清除已确认的全局X/Y。先等待100ms，过滤缓存旧反馈，再等新四轮数据；这段时间没有有效地图位姿。若暂停期间实际位置未知，应使用`hold`而非仅`reset`。
- 位姿失效只影响定位有效性，本次没有增加新的整车急停控制或自动恢复动作。后续导航需要通过原有失效检查停车，并与旧比赛控制互斥。
