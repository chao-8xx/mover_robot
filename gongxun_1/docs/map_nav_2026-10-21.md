# 道路分段导航模块

本阶段完成`APP/Src/map_nav.c`与`APP/Inc/map_nav.h`。采用原有Dijkstra、道路状态、真实位姿和底盘接口，一次只执行一条道路。没有在当前`main.c`或比赛控制中调用导航接口，没有修改底盘控制或旧BFS流程。

## 接口与运行顺序

以下为后续接入时的调用约定，当前代码没有自动启动导航：

```c
map_nav_init();
// start、goal为N0~N8；100为本次任务的电机指令速度RPM
map_nav_start(start, goal, map_unknown_allow, 100);
```

主循环先发布真实定位，再处理静止雷达建图及道路观察确认，最后周期调用`map_nav_task()`。定位通过已有`map_pose_update()`发布，不在导航中伪造X/Y。底盘仍使用现有1ms发送与计时服务。

导航必须独占底盘；后续接入时由上层选择旧比赛行驶控制或本模块，不能同时运行。开始任务时，实际位姿必须在指定起点附近、底盘空闲且地图已初始化。重复启动不会覆盖正在执行的任务，需要先`map_nav_cancel()`。取消和异常只下发一次停车，后续循环不反复发送。

`map_nav_get_result(&out)`读取状态、错误原因、最后确认节点、目标节点、下一节点、道路及路径进度。道路中间停车时，current_node仍表示最后确认到达的节点，不表示车辆实际停车位置；实际位置仍从map_pose读取。

## 状态转换

`plan → scan → align（需要转向时）→ scan → move → arrive → scan/finish`。

- plan：从当前已确认节点搜索路径，保留已知路1、未知路2的权重。
- scan：要求停稳、尚未走完的路径有效、下一道路有最新有效许可。导航不调用`map_update_confirm_free()`，观察范围必须由感知上层真正确认。
- align：复用不归零版本`car_rotate_yaw()`；通过新增只读`map_pose_yaw_offset_get()`换算地图方向与累计IMU角。转向打断静止观察，因此清除待确认信息，转完后回scan等待新许可。
- move：按实际位姿计算前进距离，mm换算cm，每条道路只下发一次`car_run_distance()`。不合并连续道路，不在下发指令时提前更新节点。
- arrive：底盘忙状态结束后，要求实际位姿进入目标范围，并由至少3次不同时间的新定位确认稳定；重复使用同一定位不能累计停稳时间。到位后才推进节点和道路索引。
- finish/stop：终点完成或异常锁定；不会在下一次循环自行恢复运动。

节点处发现剩余路径被封锁时重新规划。经过的道路后来封锁，不影响剩余路径。当前道路在行驶中变为封锁/未知、位姿失效或角度参考改变、运动偏离本段、超时或到位阶段出现其他移动指令时停车并给出原因。

## 参数和现阶段边界

节点容差30mm、路线偏差50mm、停稳观察300ms及5mm/1度变化范围、观察/转向/到位确认超时10s、单段移动超时30s、速度上限200RPM均为软件初值，尚未经实车调定。

停稳依据底盘空闲和连续定位变化，尚未接入轮速为零或驱动器到位反馈。现有底盘位置移动没有新增全程航向闭环；实际到位偏差和路线偏差会被检查，但本模块不自动补发修正位移。

运动中的近场危险检测、雷达断流停车、转向所需空间检查、道路中间停车后退回/恢复和局部贴障绕行仍待后续实现。本阶段只提供导航模块及桌面验证，不能据此认定已完成实车自动避障。
